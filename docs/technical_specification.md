# Курсовой проект: Environmental Data Logger

Основа: климатический регистратор минипроекта 6 с требованиями от 12.11.2026. Перенос в курсовую и добавление WDT с panic согласованы 13.11.2026. Исходники подготовлены для самостоятельной сборки и проверки пользователем на плате.

## 1. Оборудование и область работ

- ESP32-S3, существующая настройка flash 2 MB. Реальная маркировка памяти пока не установлена; больший объём не предполагается.
- BME280 по четырёхпроводному SPI; только разовые forced-измерения.
- RTC DS1307 по I²C. Батарейка будет установлена пользователем при подключении.
- SSD1306 128×64, адрес 0x3C. Экран, шрифт и распиновка сверены с обновлённой домашкой 5.8.
- Внешний USB–TTL-адаптер, изображённый слева на фото пользователя: UART1, GPIO17 TX / GPIO18 RX, 115200 8N1. Уровни сигналов должны быть 3,3 В.
- Курсовой проект на C с модульной структурой. Использовать подходящие модули VolkCoreEmbedded; подключать дополнительные библиотечные компоненты только при необходимости.

DS1306 на исходных скриншотах признан неоднозначностью задания; пользователь подтвердил DS1307. Дополнительные служебные задачи разрешены. Чтение архива, erase и модульная структура включены в согласованный объём работ.

## 2. Функциональные требования

1. При исправном оборудовании каждую секунду читать BME280 и RTC, обновлять OLED, затем переходить в Light Sleep на остаток периода.
2. Каждую минуту добавлять одну актуальную запись в RAM. Интервал задаётся `#define APP_LOG_INTERVAL_MINUTES`.
3. Сохранять данные во flash только целыми секторами. Нормальная запись — при заполнении буфера; явная команда flush дополняет остаток байтами 0xFF и сохраняет сектор досрочно. Эта трактовка согласована пользователем.
4. Использовать один RAM-буфер журнала размером 4096 байт. Очереди сообщений, framebuffer OLED и малые буферы UART/проверки записей к этому ограничению не относятся.
5. Выделить раздел `logdata` размером 64 КиБ. Не использовать файловую систему, wear leveling или метаданные журнала во flash/NVS.
6. При полном разделе остановить запись, сохранить старые данные, сообщить через UART и OLED. Измерения, дисплей и команды продолжают работать.
7. После перезапуска найти уже сохранённые записи, показать последнюю с отметкой ARCHIVE примерно на 1,5 секунды, затем перейти к актуальным измерениям. Не выдавать архивную запись за новое измерение.
8. Не стирать журнал автоматически при запуске. Стирание выполняется только командой erase.
9. Контролировать Manager через TWDT, а завершение запросов Sensor/Flash/Display и согласование сна — независимыми сроками. Контролировать работу UART независимо от наличия входящих команд. При зависании вызывать TWDT panic с автоматической перезагрузкой.

## 3. Задачи и взаимодействие

| Задача | Владелец и работа |
| --- | --- |
| Sensor Task | BME280, SPI, DS1307; измерения и команды установки RTC. |
| Display Task | SSD1306 и его framebuffer; вывод согласованного снимка состояния. |
| UART Task | Объект uart_t и аппаратный UART1; разбор строк, отправка ответов и диагностики. |
| Manager Task | Режим логирования, расписание, маршрутизация сообщений, управление сном. |
| Flash Writer Task | Раздел logdata и единственный секторный RAM-буфер; сканирование, накопление, запись, чтение и стирание. |
| Logger worker | Собственная очередь и служебная задача существующего logger_t; отправка текста в очередь UART Task. |

Каждый исполнитель получает запрос через свою Queue и сообщает Manager результат через очередь событий. Структуры передаются копированием, без указателей на временные данные callbacks. Для Display и Flash формируются отдельные сообщения. Manager допускает не более одного незавершённого запроса на каждого исполнителя; занятой модуль возвращает BUSY на конфликтующую пользовательскую команду.

Sensor и Display используют общий I²C Mutex. Он удерживается только во время работы с шиной; освобождается до отправки ответа. Ожидание измерения BME280 отдаёт процессор через FreeRTOS. Между запросами задачи блокируются на очередях.

| Возможность | Модули |
| --- | --- |
| BME280 forced mode | climate_bme280, spi, spi_esp |
| DS1307 | rts_ds1307, i2c, i2c_esp |
| SSD1306 | oled_SSD1306, i2c, i2c_esp |
| UART | uart, uart_esp |
| Диагностика | logger_t с sender, передающим сообщения в UART Task |

async_delay не требуется: периодами и ожиданием управляют FreeRTOS и Manager. Wi-Fi, MQTT, NTC, энкодер и EEPROM не включаются. Прикладная логика размещена в main/sensor, display, storage, uart, manager, time, watchdog. Существующие драйверы библиотеки не переписываются.

## 5. Формат и ёмкость архива

Явная сериализация 16 байт little-endian, независимо от выравнивания C-структуры:

| Смещение | Байты | Поле |
| --- | --- | --- |
| 0 | 8 | uint64 timestamp: секунды Unix UTC, дата 2000–2099 из DS1307 |
| 8 | 2 | int16: температура °C × 100 |
| 10 | 2 | uint16: влажность % × 100 |
| 12 | 4 | uint32: давление в целых мм рт. ст. |

Выполнять округление и преобразование давления из hPa. Невалидные показания или время не записывать.

4096 байт вмещают 256 записей; 64 КиБ — 4096 записей, то есть 2 суток 20 часов 16 минут при интервале одна минута. Первый полный сектор сохраняется примерно через 4 часа 16 минут после включения логирования. Это время заполнения буфера, а не предел длительности архива.

После flush свободный хвост сектора повторно не использовать. Поэтому частые досрочные flush и пропуск секторов после оборванных записей уменьшают полезную ёмкость. При отключении питания содержимое RAM теряется; при Light Sleep сохраняется.

## 6. Хранилище и перезапуск

- Использовать esp_partition в границах logdata, с проверкой размера и выравнивания сектора; шифрование данного формата не поддерживается.
- Во время запуска последовательно просканировать все сектора тем же 4096-байтным буфером; определить последний занятый сектор, количество записей, последнюю запись и число явно некорректных слотов.
- Продолжать с сектора после последнего занятого, не заполняя пропуски и хвосты прежних секторов. Не хранить указатели, счётчики, маркеры подтверждения и прочие метаданные во flash.
- Перед записью проверить, что весь следующий сектор содержит 0xFF. Записывать ровно 4096 байт; прочитать обратно малыми порциями и сравнить с RAM.
- Только после успешной записи и проверки продвигать позицию и освобождать RAM-буфер. При сбое остановить логирование и сохранить буфер; состояние ошибки не скрывать.
- erase стирает только logdata, затем повторяет сканирование. После успешного erase буфер пуст и логирование OFF.
- Проверка диапазонов полей не заменяет CRC и атомарный протокол записи. Без метаданных невозможно гарантировать выявление любого оборванного, но правдоподобного значения. Такое ограничение явно документируется.

Разделы: nvs 0x9000/0x6000; phy_init 0xF000/0x1000; factory 0x10000/0x100000; logdata 0x110000/0x10000. Конец последнего раздела 0x120000 меньше 0x200000. Существующие позиции приложения и системных разделов сохранены.

## 7. Энергосбережение и UART

Manager планирует секундные циклы по монотонному времени. Время работы вычитается из следующего периода сна. Если срок пропущен, фиксируется пропуск; устаревшие измерения не воспроизводятся серией.

Перед сном требуется завершить работу Sensor, Display и Flash Writer, дождаться logger_flush, затем запросить у UART Task завершение передачи. UART подтверждает готовность только после физического окончания TX и опустошения очереди; после подтверждения блокируется до возобновления. Manager повторно проверяет отсутствие новой работы перед esp_light_sleep_start. При отказе подготовки сон отменяется. После любой попытки сна UART возобновляется.

Таймер обеспечивает следующий период измерения; UART1 даёт дополнительное пробуждение. В ESP-IDF 6.1 используется uart_wakeup_setup и бит ESP_SLEEP_WAKEUP_UART1 из esp_sleep_get_wakeup_causes. Внутренний USB Serial/JTAG не используется для команд во сне. Документация: [Sleep Modes](https://docs.espressif.com/projects/esp-idf/en/stable/esp32s3/api-reference/system/sleep_modes.html), [USB Serial/JTAG](https://docs.espressif.com/projects/esp-idf/en/stable/esp32s3/api-guides/usb-serial-jtag-console.html#sleep-mode-considerations).

Пользователь отправляет UUU и LF, ожидает READY и вводит команду. Первые символы пробуждения не считаются командой. UART-сеанс сохраняет активность 30 секунд после последнего входящего фрагмента; измерения и логирование в этот период продолжаются. После тайм-аута возвращается периодический Light Sleep. Длинный вывод read также должен закончиться перед сном.

OLED остаётся включённым с пониженным настраиваемым контрастом, чтобы изображение было видно между пробуждениями. BME280 выполняет forced-измерения и не работает постоянно. Измеренное энергопотребление конкретной платы не заявляется.

## 8. Время

Работающий DS1307 с корректной датой не переводить при обычном старте. При остановленном генераторе или некорректных регистрах и доступной I²C-связи использовать начальную UTC-настройку, если она заполнена; иначе — UTC-метку сборки. Генерация метки выполняется каждой сборкой, включая инкрементальную.

Время сборки приблизительное: задержка до фактического запуска не компенсируется. Для коррекции предусмотрена time set. RTC и архив используют UTC; часовой пояс OLED и вывода UART задаётся POSIX-строкой в menuconfig. По умолчанию используется настраиваемое правило EET/EEST. Существующий RTC из прошлой работы мог содержать местное время — пользователь корректирует его один раз.

Время RTC нельзя восстанавливать из последней архивной записи: продолжительность отключения неизвестна. Батарейка обеспечивает дальнейший отсчёт при отключённом основном питании; её устанавливает пользователь.

## 9. Команды

| Команда | Результат |
| --- | --- |
| status | Режим, интервал, записи RAM/flash, занятое место, ошибки, состояние датчиков/OLED, счётчики сна и пропущенных интервалов, TWDT/panic и причина перезапуска. |
| log on | Включить накопление, если хранилище доступно; при переходе OFF→ON первый отсчёт через N минут. Повторное ON не сбрасывает интервал. |
| log off | Остановить новые записи; сохранить буфер, не выполнять автоматический flush. Уже принятый запрос может завершиться. |
| flush | При непустом буфере сохранить весь сектор с заполнением остатка 0xFF; при пустом ничего не записывать. |
| erase | Удалить logdata и накопленный буфер, оставить логирование OFF. |
| read | Последние 16 сохранённых записей. |
| read first count | Сохранённые записи с нулевого индекса first, count от 1 до 256; вывод: `index, 16:32:14 13-11-2026 +2 UTC: T = 23.0 C H = 50.0% P = 735 mmHg`. Подписи и единицы добавляются при выводе, температура и влажность отображаются с одним знаком после запятой; формат хранения не меняется. |
| time set YYYY-MM-DDTHH:MM:SSZ | Установить DS1307 в UTC; дата должна быть в пределах 2000–2099. |
| help | Показать команды. |

Строки заканчиваются LF или CRLF. Некорректная, слишком длинная или повреждённая строка не выполняется. При занятом модуле выводится BUSY; пользователь повторяет запрос. Ответ OK на flush/erase/time set означает завершение операции, а не только постановку в очередь. Команды erase и log off не отключают измерения и OLED.

## 10. WDT и восстановление

Manager подписывается на TWDT до выдачи стартовых уведомлений рабочим задачам. Таймаут TWDT — 5 секунд, panic включён, обработчик panic печатает диагностику и перезапускает ESP. Сохраняются системные Interrupt WDT и контроль Idle-задач обоих ядер.

Для Sensor и Display срок ответа — 3 секунды. Для Flash — 5 секунд без прогресса, включая стартовое сканирование; успешное чтение/запись/стирание продлевает срок. UART должен подтверждать выполнение своего цикла не реже одного раза за 3 секунды; подготовка ко сну имеет независимый срок 3 секунды. Сроки заданы в `main/app_config.h` и требуют проверки на плате.

Контроль выполняется и при ожидании начального сканирования, и при подготовке ко сну. Просрочка фиксируется до перезагрузки: поздние ответы не восстанавливают кормление TWDT. После обнаружения Manager остаётся бодрствовать, не отправляет новых запросов и отдаёт процессор Idle-задачам, ожидая срабатывания TWDT. Остальные задачи могут завершить уже полученные операции; аварийный flush не выполняется.

Ожидание задания в очереди и возвращённая ошибка устройства не являются зависанием. Срок UART приостанавливается после подтверждения паузы и запускается заново перед отправкой resume; Manager остаётся подписан на TWDT. Один Light Sleep ограничен 1 секундой. Собственные аппаратные WDT ESP-IDF управляются SDK; приложение их перед сном не отключает.

Сброс сохраняет уже записанный архив, но теряет RAM-буфер. Начальный scan восстанавливает доступные записи по существующему формату, без автоматического erase. Подробности и сценарии проверки: [watchdog.md](watchdog.md).

## 11. Проверка результата

Обязательные проверки на плате перечислены в [verification.md](verification.md): период измерений, UART до/после сна, накопление и flush, отрицательные температуры, часовой пояс и батарейка, восстановление после перезапуска, FULL, ошибки устройств и erase.

При подготовке исходников выполняются форматирование и проверка исходного кода, таблицы разделов и diff. Согласно инструкции пользователя сборка, проверочная компиляция, прошивка и аппаратные испытания агентом не запускаются.

Подключение и инструкция первого использования USB–TTL: [wiring_and_uart.md](wiring_and_uart.md). Дополнительных вопросов, блокирующих реализацию согласованной версии, нет.
