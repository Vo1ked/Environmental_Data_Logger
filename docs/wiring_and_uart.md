# Подключение и первый запуск USB–TTL

## 1. Оборудование

Используется ESP32-S3, DS1307 с батарейкой, BME280 с доступными CSB и SDO и SSD1306 128×64 (0x3C). GPIO экрана и BME280 взяты из обновлённой домашки 5.8. Номера ниже — номера GPIO, а не порядковые номера контактов разъёма.

## 2. Датчики и экран

| ESP32-S3 | OLED SSD1306 | RTC DS1307 |
| --- | --- | --- |
| GPIO8 | SDA | SDA |
| GPIO9 | SCL | SCL |
| GND | GND | GND |
| 3V3 | VCC для совместимого 3,3-В OLED-модуля | — |
| 5V/VBUS | — | VCC для обычного 5-В DS1307-модуля |

У самого DS1307 основное питание 4,5–5,5 В; питание конкретной платы зависит от её схемы. На SDA/SCL со стороны ESP должны быть подтяжки к **3,3 В**, а не к 5 В. Проверь подтяжки RTC-модуля до подключения общей шины; при 5-В подтяжках нужна их переделка или подходящее согласование уровней. В прошивке внутренние подтяжки I²C не включены. Источник параметров: [DS1307 datasheet](https://www.analog.com/media/en/technical-documentation/data-sheets/DS1307.pdf).

Батарейку установить с правильной полярностью; её тип должен соответствовать схеме резервного питания/заряда конкретного RTC-модуля. Батарейка поддерживает отсчёт часов, но не заменяет основное питание для обычной работы I²C.

| ESP32-S3 | BME280, четырёхпроводный SPI |
| --- | --- |
| 3V3 | VCC/VIN, если модуль допускает такое питание |
| GND | GND |
| GPIO11 | SDA/SDI/MOSI |
| GPIO13 | SDO/MISO |
| GPIO12 | SCL/SCK |
| GPIO10 | CS/CSB |

Четырёхконтактный I²C-модуль BME280 без CSB/SDO для этой схемы не подходит. У устройств общая земля. NTC, энкодер и ST-LINK здесь не подключаются.

## 3. USB–TTL с фотографии

Нужен **левый чёрный адаптер с надписью USB TO TTL**. Жёлтый ST-LINK справа для этого проекта не используется.

1. Отключи питание перед подключением проводов.
2. Проверь маркировку микросхемы адаптера и уровни TXD/RXD. Нужна логика **3,3 В**. Перемычка 3V3/5V на некоторых платах переключает только выход VCC, поэтому сама надпись не гарантирует уровень TXD. Если назначение неизвестно, сначала проверь документацию платы и напряжение TXD в покое относительно GND.
3. Подключи три провода:

   | Контакт USB–TTL | ESP32-S3 | Направление |
   | --- | --- | --- |
   | TXD | GPIO18 | Адаптер передаёт → ESP принимает |
   | RXD | GPIO17 | ESP передаёт → адаптер принимает |
   | GND | GND | Общая земля |

4. **VCC, 5V и 3V3 адаптера оставить неподключёнными**, если ESP питается от собственного USB.
5. Подключи USB платы ESP для питания/прошивки и USB адаптера к компьютеру. Для команд нужен COM-порт именно адаптера, не ESP.
6. В Windows открой «Диспетчер устройств → Порты (COM и LPT)». Посмотри, какой COM появляется при подключении адаптера. Название и драйвер зависят от его микросхемы; по этому фото её модель не установлена.
7. Открой этот COM в привычном serial-терминале: **115200 бод, 8 data bits, no parity, 1 stop bit, flow control None**. Завершение строки LF либо CRLF. Если ввод не виден — включи local echo в терминале.

GPIO17/18 выбраны для отдельного UART1 и не пересекаются с датчиками. Если они заняты особенностями конкретной платы, поменяй EDL_UART_TX_GPIO/EDL_UART_RX_GPIO в menuconfig и соответствующие провода.

## 4. Пробуждение и команды

После запуска устройство выдаёт READY и оставляет 30 секунд для ввода. Если оно уже спит:

1. Отправь `UUU` с переводом строки.
2. Дождись `READY`. При отсутствии ответа повтори пробуждающую строку.
3. Отправь `status` с переводом строки.

Не отправляй пробуждение и важную команду одним пакетом: дождись READY. Первые символы могут потеряться при пробуждении. Каждый входящий фрагмент продлевает активный сеанс на 30 секунд. Во время сеанса ESP не входит в Light Sleep, но продолжает измерения и логирование. После паузы режим сна возобновляется.

Встроенный USB ESP может терять соединение во время Light Sleep; для команд используется внешний адаптер. [Объяснение Espressif](https://docs.espressif.com/projects/esp-idf/en/stable/esp32s3/api-guides/usb-serial-jtag-console.html#sleep-mode-considerations).

## 5. Первый запуск

1. Самостоятельно собери и прошей проект вместе с новой таблицей разделов. В menuconfig должна быть выбрана Custom partition table: `partitions.csv`; flash остаётся 2 MB. Здесь нет команды автоматического стирания архива при запуске.
2. Подключись к COM адаптера, получи READY, выполни `status`.
3. Установи точное текущее время в UTC: `time set YYYY-MM-DDTHH:MM:SSZ`. Например, `time set 2026-11-12T12:00:00Z` демонстрирует формат; не используй эту дату как актуальную.
4. Экран показывает местное время по настройке EDL_TIMEZONE; `status` и `read` выводят местное время в формате `HH:MM:SS DD-MM-YYYY +N UTC` с фактическим смещением для даты записи. Если RTC из прежнего проекта содержал местное время, требуется однократная коррекция.
5. Через минуту в `status` появится первая запись в RAM. Выполни `flush`, дождись `OK: flush`, затем `read`. Должна появиться строка с сохранённым измерением, например: `0, 16:32:14 13-11-2026 +2 UTC: T = 23.7 C H = 51.6% P = 735 mmHg`. Подписи и единицы добавляются только при выводе; формат хранения не меняется.
6. Перед плановым отключением: `log off`, дождаться ответа, `flush`, дождаться OK, затем выключить питание. Если ответ BUSY — дождаться завершения текущей операции и повторить команду.

## 6. Полезные команды

| Команда | Что делает |
| --- | --- |
| status | Состояние устройств, RAM/flash, режим и счётчик Light Sleep. |
| log off / log on | Выключить/включить новые архивные записи. |
| flush | Сохранить накопленное, расходуя один сектор при непустом буфере. |
| read | Последние 16 сохранённых записей; RAM не выводится. |
| read 0 100 | До 100 записей, начиная с нулевого индекса; максимум 256 за запрос. |
| erase | Немедленно удалить журнал и RAM-буфер; после завершения логирование остаётся OFF. |
| help | Краткая справка. |

При FULL данные остаются доступны через read. Для нового журнала пользователь явно выполняет erase, затем log on. Архив не является кольцевым.

Если ответа нет: проверь COM адаптера, общую землю, перекрёстное соединение TX/RX, уровни 3,3 В, скорость и LF/CRLF. Если экран показывает BME280 ERROR — проверь SPI и наличие именно BME280; BMP280 без влажности не подходит. RTC ERROR означает недоступные/некорректные часы. Ошибка одного устройства не должна останавливать доступные функции; физически удерживаемая SDA/SCL может одновременно нарушить работу RTC и OLED.
