# Проверка курсового проекта Environmental Data Logger

Сборка и аппаратная проверка выполняются пользователем. Подготовка исходников агентом не является подтверждением работы прошивки на оборудовании.

## Проверки без компиляции

- Форматирование изменённых C/H по .clang-format, ColumnLimit 400.
- Проверка diff на пробельные ошибки.
- Проверка существования исходников CMake, используемых конфигурационных символов и границ partitions.csv.
- Сверка вызовов UART wakeup, причин пробуждения, esp_partition и интерфейсов VolkCoreEmbedded с локальными заголовками ESP-IDF 6.1 и библиотеки.
- Анализ владения устройствами, очередей, I²C mutex, подготовки ко сну, сценариев FULL, ошибки flash, перезапуска и заполнения 0xFF.
- Анализ независимых сроков WDT, их постановки до отправки заданий, фиксации просрочки, стартового сканирования и паузы UART во время сна.
- Сверка TWDT API с локальными заголовками ESP-IDF 6.1; проверка настроек panic в sdkconfig и sdkconfig.defaults.

## На плате

| Проверка | Действия и ожидаемый результат |
| --- | --- |
| Первый запуск | Подключить оборудование по wiring_and_uart.md. READY, OLED обновляется каждую секунду, status сообщает доступные устройства. |
| UTC/батарейка | time set с актуальным UTC. Отключить питание при установленной исправной батарейке; после запуска время продолжилось, не вернулось к времени сборки. |
| Light Sleep | Не отправлять данные более 30 секунд. Затем UUU + LF, дождаться READY и status: счётчик сна увеличился. Повторить несколько раз, включая команды вблизи секундного пробуждения. |
| WDT без ошибок | `status` сообщает WDT=ON, timeout=5 s, panic=ON. Несколько минут выполнять status/read, затем оставить устройство без команд для Light Sleep: самопроизвольных сбросов нет. |
| WDT при зависании | Выполнить отдельные сценарии Sensor/Manager/Flash/UART/согласования сна из [watchdog.md](watchdog.md). Ожидаются диагностика, TWDT panic, перезапуск и восстановление сохранённого архива. |
| Накопление | После log on первая запись в RAM примерно через минуту; до полного буфера occupied не растёт. При повторном log on расписание не сбрасывается. |
| Flush | После 1–2 записей выполнить flush: RAM=0, saved вырос на число реальных записей, occupied вырос на 4096. Повторный flush пустого буфера не расходует сектор. |
| Read | read и read 0 16 выводят правильные UTC, T/H/P и индекс. read 0 257, отрицательные индексы и неверные аргументы отвергаются. |
| Перезапуск | После flush перезагрузить ESP: сначала ARCHIVE с сохранёнными значениями, затем свежие измерения; новые записи не перезаписывают предыдущий сектор. |
| Log off | Измерения/экран продолжаются, новых записей в RAM нет, старый буфер сохранён. |
| FULL | На тестовом архиве повторить 16 раз: дождаться хотя бы одной новой записи, flush. По окончании 16 секторов OLED/UART сообщают FULL, log on отвергается, read работает. Эта проверка расходует журнал, поэтому сначала сохранить нужные данные. |
| Erase | По явной erase стирается только logdata, RAM/saved/occupied обнуляются и режим OFF. После log on запись возобновляется. |
| Ошибки устройств | Отключать устройство при снятом питании, затем запускать: без BME280 часы/экран/UART работают, без RTC климат отображается, неполные записи не архивируются. При восстановлении связи драйверы повторяют попытки. |
| Невалидный ввод | Неизвестная/длинная строка, неверная дата, 29 февраля невисокосного года, порции одной строки, CRLF: ошибка не выполняет команду и не повреждает следующую строку. |
| Долгое чтение | read 0 256: экран продолжает обновляться, до завершения чтения сон не начинается, конфликтующая операция возвращает BUSY. |
| Потеря питания | Незаписанный RAM-буфер теряется. После оборванной записи занятый сектор не используется повторно; правдоподобное повреждение может не обнаруживаться без CRC, что является ограничением формата. |

Отрицательные температуры проверять на доступном реальном измерении или на отдельно подготовленных данных при будущих тестах формата; результат должен сохранять знак и масштаб ×100. Чтобы проверить полный сектор без ожидания 256 минут, можно добавить отдельный тестовый источник данных в последующей работе; штатный интервал и данные этой реализации не подменяются ускоренными тестовыми значениями.
