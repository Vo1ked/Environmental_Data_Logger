# Перевірка та критерії приймання

Документ описує відтворювані сценарії перевірки. Результати апаратних випробувань потрібно фіксувати для конкретної плати й версії прошивки; цей перелік не є звітом про випробування.

## Вихідний код і конфігурація

- Форматування C/H за `.clang-format`, ColumnLimit 400; diff без помилок пробілів.
- Усі вихідні файли підключені до CMake; параметри EDL визначені у Kconfig.
- Розділ 0x80000/0x174000 не перетинається із застосунком і вміщується у 2 МіБ.
- 31 слот × 48 КіБ; 3070 позицій на слот достатньо для 2880 записів з інтервалом 30 секунд.
- Незалежні строки WDT діють під час початкового сканування, ротації та підготовки сну.

## Апаратні сценарії

| Сценарій | Очікуваний результат |
| --- | --- |
| Вимірювання й UART | OLED оновлюється щосекунди; status показує стан пристроїв |
| Відсутній датчик | Помилкові поля позначені; неповні записи не зберігаються; штатна відповідь задачі не спричиняє WDT reset |
| UTC та батарейка | RTC продовжує відлік після вимкнення основного живлення |
| Light Sleep | Через 30 с без введення зростає лічильник сну; UUU + LF пробуджує пристрій; READY передує команді |
| Часті flush | Зберегти кілька записів окремими flush; усі читаються й використовують один добовий слот |
| Повний буфер | 64 записи зберігаються автоматично; наступний запис не пошкоджує попередні |
| Повна доба | 2880 різних 30-секундних інтервалів уміщуються в один слот; CRC та порядок коректні |
| Межа UTC | Записи о 23:59 та 00:00 належать різним слотам; попередній RAM-буфер збережений |
| 32 дні | У тестовому архіві послідовно встановити 32 дати, дочекатися запису й виконати flush; перший день зникає, останній 31 день читається за порядком |
| Пропуски дат | Перехід уперед на 5, 31 і 62 дні залишає лише записи поточного вікна, без штучних даних |
| Переведення часу назад | Раніший архівний інтервал відхиляється, накопичення зупиняється; після корекції та log on поновлюється |
| Повторний інтервал | Другий запис того самого 30-секундного інтервалу не створює дубль |
| Перезапуск | ARCHIVE показує останній валідний запис; read зберігає хронологію після оберту кільця |
| Переривання запису | Незавершений запис відхиляється за CRC; наступний запуск не перезаписує зайняті байти |
| Переривання ротації | Вимкнення на кожному секторі erase та між записом заголовка і маркера не пошкоджує інші дні |
| Тривале читання | read 0 256 працює без WDT; конфліктні команди отримують BUSY |
| Очищення | erase очищає архів і RAM та залишає OFF; log on створює новий добовий слот |
| Попередня розмітка | До оновлення експортувати архів; після оновлення виконати erase та log on |
| WDT | Сценарії Sensor, Display, Flash, UART, Manager і підготовки сну з [watchdog.md](watchdog.md) спричиняють panic/reboot |

Для прискореної перевірки дат використовується окремий тестовий архів і команда встановлення UTC. Сценарії зі стиранням та втратою живлення виконуються після експорту потрібних даних. Перевірка місткості повного дня потребує записів кожні 30 секунд або окремого стендового джерела вимірювань.
