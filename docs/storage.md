# Добовий архів v2

## Розміщення

`logdata` містить 31 слот по 49152 байти — 12 секторів по 4096 байтів. День визначається як `timestamp / 86400`, фізичний слот — `day % 31`. Вікно охоплює день останнього прийнятого запису та 30 попередніх днів UTC. Поки запис вимкнений або немає коректних вимірювань, ротація не виконується.

На початку слота розташований заголовок на 32 байти, далі — 3070 позицій по 16 байтів. Для запису кожні 30 секунд потрібно максимум 2880 позицій; 190 залишаються резервом на пошкоджені записи. Окремі сектори для кожного flush не виділяються.

## Заголовок

Усі поля — uint32 little-endian; платформа ESP32-S3 також little-endian.

| Зміщення | Поле |
| --- | --- |
| 0 | Magic 0x324C4445 (`EDL2`) |
| 4 | Версія 2 |
| 8 | Номер доби UTC |
| 12 | Побітове заперечення номера доби |
| 16 | Розмір слота 49152 |
| 20 | Розмір запису 16 |
| 24 | CRC32 перших 24 байтів |
| 28 | Маркер завершення 0x51A7C0DE |

Спочатку записуються перші 28 байтів, потім окремою операцією — маркер завершення. Заголовок перевіряється читанням. Некоректні CRC, версія, розмір або невідповідність номера дня фізичному слоту виключають слот із відновлення.

## Запис

| Зміщення | Тип | Значення |
| --- | --- | --- |
| 0 | uint32 | Unix timestamp UTC, 2000–2099 |
| 4 | int16 | Температура ×100, °C |
| 6 | uint16 | Вологість ×100, % |
| 8 | uint32 | Тиск, мм рт. ст. |
| 12 | uint32 | CRC32 перших 12 байтів |

CRC32: відображений поліном 0xEDB88320, початкове значення 0xFFFFFFFF, інверсія результату. Перевіряються CRC, допустимі діапазони, належність запису до дня та строге зростання номера 30-секундного інтервалу.

## Збереження та ротація

Буфер містить до 64 записів. Під час flush записуються лише зайняті байти з подальшим порівнянням із flash. Нові записи розміщуються безпосередньо після збережених. Перед записом перевіряється, чи цільові байти стерті.

Під час зміни дня спочатку зберігається старий буфер. Цільовий слот стирається посекторно, починаючи із заголовка; потім створюється новий заголовок. Дні за межами вікна також звільняються. Якщо живлення зникає після видалення старого дня, але до завершення нового заголовка, слот залишається недоступним до повторної ініціалізації. Решта слотів незалежні.

Під час запуску індекс відновлюється із flash. Курсор запису встановлюється після останньої зайнятої позиції, включно з пошкодженими записами. Це запобігає повторному програмуванню незавершеного запису. Дні поза вікном відносно найновішого валідного заголовка не видаються через read навіть після перерваного очищення. Відновлення не виконує автоматичного форматування.

`read first count` використовує відносний індекс серед валідних збережених записів від старих до нових. RAM не включається. Після ротації індекси зміщуються. Повторний 30-секундний інтервал не додається; раніший відхиляється, а накопичення зупиняється до виправлення часу та `log on`.

## Перехід із попередньої розмітки

Нова розмітка несумісна з лінійним журналом та попередніми слотами v2 по 24 КіБ; розділ архіву тепер починається з 0x80000. Потрібні записи слід вивантажити попередньою прошивкою до оновлення. Після встановлення нової таблиці розділів виконати `erase` та `log on`. Виявлення старого UTC timestamp на початку розділу повертає ESP_ERR_NOT_SUPPORTED замість автоматичного видалення.

## Обмеження

CRC не замінює резервну копію. RAM-буфер втрачається під час скидання. За штатного інтервалу повне заповнення буфера триває 32 хвилини; для зменшення можливого обсягу втрачених даних слід частіше виконувати flush. Втрата живлення під час стирання може видалити старий день до появи нових даних. Якщо через пошкодження вичерпано 3070 позицій одного дня, запис зупиняється з помилкою. Архів розрахований на незашифровану flash.
